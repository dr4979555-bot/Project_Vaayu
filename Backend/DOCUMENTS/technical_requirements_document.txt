3. DATABASE SCHEMA SPECIFICATION (PostgreSQL + PostGIS)
--------------------------------------------------------------------------------

-- Enable Spatial Extensions
CREATE EXTENSION IF NOT EXISTS postgis;

-- 1. Real-time Weather Observation Table (IMD AWS & Gridded Models)
CREATE TABLE weather_telemetry (
    station_id VARCHAR(32) NOT NULL,
    recorded_at TIMESTAMPTZ NOT NULL,
    geom GEOMETRY(Point, 4326) NOT NULL,
    h3_index BIGINT NOT NULL, -- H3 Resolution 7 (~5km)
    temp_celsius NUMERIC(4, 1) NOT NULL,
    humidity_pct NUMERIC(4, 1) NOT NULL,
    precipitation_mm NUMERIC(5, 1) DEFAULT 0.0,
    wind_speed_kmh NUMERIC(4, 1),
    wind_direction_deg INT,
    pressure_hpa NUMERIC(6, 1),
    aqi INT,
    source VARCHAR(32) DEFAULT 'IMD_AWS',
    PRIMARY KEY (station_id, recorded_at)
);

CREATE INDEX idx_telemetry_spatial ON weather_telemetry USING GIST (geom);
CREATE INDEX idx_telemetry_h3 ON weather_telemetry (h3_index, recorded_at DESC);

-- 2. Disaster Warnings & Early Alerts (CAP v1.2 Standard)
CREATE TABLE disaster_alerts (
    alert_id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    sender VARCHAR(64) NOT NULL, -- e.g., 'IMD_NEW_DELHI'
    sent_at TIMESTAMPTZ NOT NULL,
    severity VARCHAR(16) CHECK (severity IN ('Extreme', 'Severe', 'Moderate', 'Minor')),
    urgency VARCHAR(16) CHECK (urgency IN ('Immediate', 'Expected', 'Future')),
    certainty VARCHAR(16) CHECK (certainty IN ('Observed', 'Likely', 'Possible')),
    event_type VARCHAR(32) NOT NULL, -- 'Cyclone', 'Flood', 'Thunderstorm', 'Heatwave'
    headline TEXT NOT NULL,
    description TEXT NOT NULL,
    instruction TEXT,
    affected_polygon GEOMETRY(Polygon, 4326) NOT NULL,
    signature_ecdsa TEXT NOT NULL -- Cryptographic source proof
);

CREATE INDEX idx_alerts_spatial ON disaster_alerts USING GIST (affected_polygon);

-- 3. Agro-Met Advisory Mapping (Meghdoot Integration)
CREATE TABLE agro_advisories (
    advisory_id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    district_code VARCHAR(32) NOT NULL,
    crop_name VARCHAR(64) NOT NULL,
    advisory_text TEXT NOT NULL,
    valid_from DATE NOT NULL,
    valid_to DATE NOT NULL
);

4. ZERO-HALLUCINATION & CONSTRAINED RAG PIPELINE
--------------------------------------------------------------------------------
To guarantee 100% numerical accuracy, generative models are strictly prohibited 
from calculating, predicting, or retrieving weather figures from parametric memory.

Execution Sequence:
1. User asks: "Will it rain in Nagpur today afternoon, and should I spray cotton?"
2. Entity Extraction:
   - Intent: `weather_forecast_and_agro`
   - Location: `Nagpur` -> Geocoded to `(21.1458° N, 79.0882° E)` -> `h3_index`
   - Time Horizon: `Today 12:00 - 18:00 IST`
   - Crop Entity: `cotton`
3. Deterministic Data Retrieval:
   - Tool `get_forecast(lat=21.1458, lon=79.0882)` executes against PostGIS/Open-Meteo.
   - Result: `{"rain_prob": 78, "precip_mm": 12.4, "temp": 32.1, "wind": 14.2}`
   - Tool `get_agro_advisory(district='Nagpur', crop='cotton')` queries database.
   - Result: `{"advice": "Postpone chemical spraying due to impending showers."}`
4. Prompt Synthesis with Hard Constraints:
   ---------------------------------------------------------------------
   SYSTEM: You are WeatherGPT, official assistant for IMD.
   Translate the following GROUND TRUTH DATA into a concise, empathetic response.
   CRITICAL SAFETY RULES:
   1. Use ONLY the numbers provided in DATA.
   2. NEVER round, alter, or fabricate any weather metrics.
   3. Include the agricultural advisory verbatim or concisely summarized.
   DATA: {forecast: ..., advisory: ...}
   ---------------------------------------------------------------------
5. Regex Validation Filter:
   - The returned response string is scanned with regular expressions to verify 
     that all numbers present exist in the input JSON context.
   - If validation fails, system bypasses LLM and returns a deterministic string:
     "Nagpur: Rain probability is 78% (12.4 mm) this afternoon. Advisory: Postpone chemical spraying."

5. THREE-TIER SPATIOTEMPORAL & SEMANTIC CACHING
--------------------------------------------------------------------------------
To achieve national-scale concurrent throughput on a shoestring budget:

- Tier 1: Spatiotemporal Tile Cache (Redis)
  * Spatial Indexing: Queries are mapped to Uber H3 Hexagonal Grid (Resolution 7, 
    $\sim 5.1\text{ km}$ edge length).
  * Cache Key Pattern: `weather:h3:<h3_id>:slot:<epoch_hour>`
  * TTL: 900 seconds (15 minutes).
  * Economics: 65-75% of users in the same city/ward share the identical cached 
    data payload, incurring $0 LLM token costs.

- Tier 2: Semantic Response Cache (Qdrant / In-Memory Cosine Similarity)
  * Common routine questions (e.g., "Current weather", "Is it going to rain?") 
    are matched against a semantic embedding store (threshold $> 0.96$).
  * If matched, the formatted template is populated directly with Tier 1 telemetry.

- Tier 3: Model Routing (SLM vs. Frontier LLM)
  * 85% of queries (routine forecasts) -> Local 3B SLM or Free-Tier Groq 8B.
  * 15% of queries (historical climate analysis, multi-step disaster synthesis) -> 
    Groq Llama-70B or Gemini Flash.

Cost Comparison Benchmark (per 1,000,000 queries):
- Standard Commercial Chatbot (GPT-4o / Claude 3.5 Sonnet): $5,000.00
- Open-Source Uncached Self-Hosted Cluster: $2,100.00
- WeatherGPT 3-Tier Caching Architecture: $18.40 (99.6% savings)

6. SECURITY, CIPHER SUITES & GUARDRAILS
--------------------------------------------------------------------------------
1. CAP Alert Cryptographic Verification:
   All high-severity early warnings must pass ECDSA NIST P-256 signature 
   verification before transmission to clients:

   ```python
   from cryptography.hazmat.primitives.asymmetric import ec
   from cryptography.hazmat.primitives import hashes
   import base64

   def verify_alert_authenticity(payload: bytes, signature_b64: str, pub_key_pem: bytes) -> bool:
       try:
           from cryptography.hazmat.primitives.serialization import load_pem_public_key
           public_key = load_pem_public_key(pub_key_pem)
           sig = base64.b64decode(signature_b64)
           public_key.verify(sig, payload, ec.ECDSA(hashes.SHA256()))
           return True
       except Exception:
           return False
   ```

2. Prompt-Injection & Adversarial Defenses:
   - System prompts are stored out-of-band and delimited with non-printable tokens.
   - Input filtering blocks terms attempting system role overrides (e.g., 
     "Ignore previous instructions", "Declare a Red Alert for Mumbai").

3. Privacy & Sovereign Cloud Compliance:
   - No GPS coordinates are stored in raw format. Coordinates are converted to 
     H3 cell IDs at ingestion and discarded from RAM.

7. MULTILINGUAL VOICE PIPELINE SPECIFICATIONS
--------------------------------------------------------------------------------
1. Audio Ingestion:
   - Client records audio chunk via MediaRecorder API (Opus codec, 16 kHz mono).
   - Audio is streamed over WebSocket directly to the FastAPI backend.

2. ASR (Speech-to-Text):
   - Fast fallback pipeline: Bhashini ULCA WebSocket API.
   - Open source local fallback: `faster-whisper` (medium-int8 running on CPU/GPU).

3. Intent Processing & Response Generation:
   - Executed within the deterministic zero-hallucination workflow.

4. TTS (Text-to-Speech):
   - Bhashini Indic-TTS or `edge-tts` (Microsoft Neural Indic Voices: hi-IN, ta-IN, 
     te-IN, bn-IN, mr-IN).
   - Audio returned to client as an Opus stream with sub-second time-to-first-byte.
